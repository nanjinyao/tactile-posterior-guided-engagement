## 0. One-Sentence Direction

The new project should be a clean, evidence-tracked implementation of:

```text
coarse visual prior
-> randomized initial offset within visual/camera error
-> guarded downward / spiral contact search
-> small action-conditioned F/T probes
-> contact-state / probe-outcome classifier
-> set-valued belief or prediction set
-> conservative rule recovery
-> insertion / engagement verification
```

The central claim is not "NN controls the screwdriver". The central claim is:

```text
safe physical probing makes hidden contact state partially observable;
learning reads the action-conditioned F/T event;
classical guarded control owns safety and execution.
```

| classifier predicts center coordinates | old project already established this is the wrong contract |
| simulation proves real-robot success | simulation is semi-qualitative support only |
| exact center refinement as default task | optional diagnostic after engagement, not the core objective |

## 2. Meeting-Derived Requirements

The latest meeting made the required presentation and implementation logic very
explicit. The new path should answer these questions before adding complexity.

| Meeting question | New-path requirement |
|---|---|
| How is the data sampled? | Record initial offset distribution, contact band, action primitive, seed, geometry, clearance, and whether any true-center information was used. |
| What is the label? | Use event/control labels: `no_contact`, `plane`, `near_edge`, `inserted`, `ambiguous_jam`, `unsafe`, `slide`, `block`, `drop`. Do not call these "the true robot state" without qualification. |
| What model is it? | State exact model family and inputs: KNN / MLP / sequence baseline / conformal gate. |
| Where are the results? | Every experiment must write a machine-readable result and a human-readable summary. |
| What does the classifier output? | A contact class or prediction set, not an action unless a separate action-selection experiment is explicitly defined. |
| Is the pipeline leaking the answer? | Initial points must not be generated by moving toward the true center; visual prior error must be explicit. |
| What is the baseline? | Compare against ordinary spiral / fixed search / rule baseline before claiming improvement. |
| What is the next action after classification? | Define the rule: singleton cue, uncertain set, unsafe set, verify, retreat, re-probe. |

## 5. Old Project Experience To Keep

### 5.1 Claim boundary discipline

Old project lesson:

```text
aligned-orientation Allen-hex peg-in-hole engagement
is not the same claim as full autonomous unscrewing.
```

Keep this separation:

| Claim type | Allowed wording |
|---|---|
| contact-state probing | "F/T response under known action can classify contact event under stated geometry." |
| engagement | "The controller can verify inserted / engaged under stated conditions." |
| center refinement | "Paired boundary probing can estimate center after accepted boundary events." |
| unscrewing | Do not claim unless thread torque, screw rotation, extraction, and real task evidence exist. |

### 5.2 Diagnostic cue vs terminal verifier

Old project repeatedly showed that a cue can be informative without being a
safe stop condition.

| Cue | Correct role |
|---|---|
| press/twist torque | diagnostic for coupling or near-center, not terminal proof by itself |
| drop / landed event | candidate insertion cue, must be verified |
| center classifier | contact-state trigger, not center estimator |
| conformal set | uncertainty-aware gate, not a policy |
| oracle state | upper bound, not learned runtime behavior |

### 5.3 Do not leak true center

One old failure mode was paths that visually looked successful because the
script effectively knew where the center was.

New rule:

```text
All initial offsets must be generated from an explicit visual-error model.
The tool may start near the prior, but it must not move directly toward true center unless that is a named oracle baseline.
```

When using an oracle, label it in:

- command name
- output folder
- summary
- plots
- slide captions

### 5.4 Physics first, learning narrow

The useful structure is:

```text
physical bottleneck
-> safe probe that excites it
-> compact event label / prediction set
-> conservative controller
-> small learning module at the observation bottleneck
```

Learning is appropriate for:

- action-conditioned F/T sequence to contact event
- finite prediction set / confidence
- choosing among a small number of recovery options after enough transition data exists

Learning is not appropriate first for:

- raw torque/velocity policy
- replacing force caps
- hiding a poorly specified task
- proving generalization without geometry/randomization evidence

## 6. Old Project Technical Lessons

### 6.1 Source-canonical model should be the default

The old project migrated from plate abstraction to:

```text
configs/allen_m8_source_canonical.yaml
```

Important inherited model ideas:

- fixed socket-head screw
- circular head
- internal Allen recess
- true sloped micro-chamfer
- vertical hex socket walls
- matching bit
- source mode for videos and main simulation

New path should start from the source-canonical logic, not the older enlarged
plate demo.

### 6.2 Free-space spiral assumptions must be physically checked

Old project found that the supposed free-space pre-contact spiral was sometimes
not physically real because gravity / impedance sag caused early contact.

New rule:

Before claiming a search primitive:

- check actual tip trajectory, not just command trajectory
- log first-contact time, first-contact radius, peak force, and touchdown force
- distinguish command path from measured path
- verify whether "landed" means true capture or only depth threshold

### 6.3 Coverage and capture radius matter

For aligned hex insertion, the geometric bottleneck is a capture basin, not just
"make a spiral".

Keep these quantities explicit:

```text
r_cap = a_open - a_tip
pitch <= 2 * r_cap
```

For no-leadin or tight clearance, a coarse spiral can miss the capture region.
If the pitch violates coverage, do not explain failure as a classifier problem.

### 6.4 Action-conditioned sensing is load-bearing

Single static F/T is under-informative. The old project's useful insight is that
known actions expose different hidden states:

| Action | What it exposes |
|---|---|
| `press_read` | no-contact / plane / inserted / jam-like vertical response |
| `press_rotate_small` | torsional response, yaw/coupling cue |
| `lateral_probe_px/nx/py/ny` | slide / block / drop through directional stiffness and motion deficit |
| guarded spiral | low-force search plus natural radial/tangential excitation |

Any new dataset must save the `action_id`. A classifier without action context
is not the main method.

### 6.5 Press is weaker than probe

Old Stage-1 evidence:

```text
press selected model: knn
probe selected model: small_mlp
press macro-F1 around 0.587
probe macro-F1 around 0.763 on split_v4
pooled probe conformal macro-F1 around 0.871
pooled probe conformal coverage around 0.956
```

Interpretation:

- lateral probe events are already useful for a gate candidate
- press remains ambiguous and should not be trusted as a terminal gate
- conformal sets are better than pretending every prediction is certain

### 6.6 Hard safety always overrides learning

The old Stage-1 trigger used hard gates:

```text
F_pred < F_max
Ft < Ft_max
|tau_z| < tau_z_max
wrench_risk < 1
```

New rule:

```text
unsafe in prediction set -> retreat
hard safety fail -> retreat
uncertain set -> re-probe or guarded slow spiral
singleton safe cue -> controller may consider it
```

The learned model never has authority to continue through a force/torque safety
violation.

### 6.7 Bisection / bracketing is optional refinement

Old project had a center-localization branch using paired boundary probing.
That remains useful, but it should not dominate the new first version.

Correct framing:

| Use bracketing when | Avoid making it default when |
|---|---|
| precise center estimate is the experiment goal | the task is simple insertion/engagement |
| boundary events are reliable | uncertain `slide/drop` events are common |
| comparing localization methods | a chamfered guarded spiral can already seat the bit |

### 6.8 Videos must be diagnostic, not decorative

Old preference:

```text
default video = source_canonical_full_fsm_debug.mp4
```

New rule:

- generate debug videos only when they explain a mechanism or failure
- overlays should show actual tip path, force arrows, torque, contact/candidate events, and labels
- never use a clean claim video to hide failure modes
- keep video generation opt-in to avoid clutter

## 8. Baseline Ladder

Do not jump directly to the most complex model. Use a ladder.

| Level | Purpose |
|---|---|
| ordinary spiral / fixed search | basic non-learning baseline |
| hand-rule threshold | interpretable lower bound |
| KNN / logistic / small MLP on physics features | first learned trigger |
| raw sequence baseline | tests whether time-series adds value |
| split-conformal set | calibrated uncertainty |
| gated probe mode | online use of classifier in a narrow place |
| full recovery policy | only after transition data exists |

Each new claim must say which level it beats and under what seed/regime.

## 11. Before Any Claim, Ask These Checks

1. What hidden state is blocking the task?
2. What action makes that hidden state observable?
3. What exact signal or feature changes after that action?
4. Is the label a control-useful event or an overclaimed "state"?
5. Does the model see any forbidden information?
6. Is the initial offset sampled from a visual-error prior?
7. Is this oracle, shadow, or routed runtime?
8. What does hard safety do if the classifier is wrong?
9. What baseline is being beaten?
10. What artifact proves the number?
11. What does this still not prove?

## 12. Communication Rule

For group meeting or advisor updates, use this order:

```text
physical assumption
-> observable cue
-> action/sampling design
-> learning/control role
-> current evidence
-> current boundary
-> next decision
```

Avoid:

- "I tried many things" chronology
- vague "NN works better" claims without table/confusion
- over-detailing simulation internals before explaining the logic
- saying "state" when the correct word is "classified event" or "prediction set"
- saying "unscrewing solved" when only engagement is tested

## 14. Decision Rule For The ChatGPT Roadmap

On 2026-07-09, a separate ChatGPT discussion proposed a broad plan covering
M8/M10/M12 modeling, source-style baselines, geometry-aware spirals, contact
area reasoning, conical/nutation probing, and active contact geometry
estimation.

The decision for this clean path is:

```text
Treat that plan as a medium-term roadmap, not the immediate implementation scope.
```

### Absorb now

| Suggestion | How to use it in the new path |
|---|---|
| fixed Allen socket-head engagement, not full unscrewing | keep as the task definition |
| source paper's 1-2 mm visual residual, 5 N spiral, 0.1 Nm torque threshold | use as source-style baseline / motivation, not as proof of our method |
| M8 as source-canonical first model | use as the default implementation and evidence scope |
| no true-center leakage | enforce through explicit visual-error offset sampling |
| action-conditioned F/T probing | keep as the core data/model contract |
| clearance and micro-chamfer as controlled variables | document as simulation variables, not exact manufacturing standards |
| source-style spiral baseline | compare under the same initial-offset distribution |
| conical/tilt/nutation probe | keep only as optional future disambiguation primitive |

### Defer

| Suggestion | Why deferred |
|---|---|
| M10/M12 full experiments | they are scale sweeps after the M8 loop works |
| all-size generalization claim | meeting priority is first to make the basic pipeline concrete |
| information-gain active planner as the main method | promising, but it changes the project from Stage-1 trigger into belief-space planning |
| one probe plus CAD gives the true center | overclaim; observability must be proven first |
| replacing spiral entirely | not first-version safe; use source-style spiral as baseline and guarded search as bootstrap |
| proving faster than the real RCIM system | compare only to a source-inspired baseline inside the same MuJoCo benchmark |

### Current priority order

```text
1. M8 geometry sanity
2. visual-error offset sampling and no true-center leakage check
3. source-style spiral / threshold baseline
4. M8 action-conditioned F/T dataset
5. classifier + conformal gate with confusion/per-class evidence
6. gated recovery smoke with hard safety override
7. only then: M10/M12, conical probing, active information-gain planner
```

The detailed decision record is `DESIGN_DECISIONS.md`.
